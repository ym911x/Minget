# 1.6.3 概要完整高度修正

日期：2026-10-01（Asia/Shanghai），接续 `3eed73d`，仍在 `codex/minget-1-6-3` 本机迭代。

## 需求与原因

用户现场增加到七个账号后，概要最后一行被截住，需要滚动。要求概要面板拉长、全部行完整可见且无滚动条；三个 Google 的完整详情继续允许滚动。

原先 `presentationHeight`、`viewportHeight` 和 SwiftUI 默认高度均受 640 pt 限制。概要共有 152 pt 固定区域，每个账号占 64 pt 卡片及 12 pt 间距，七行需要 684 pt，原 640 pt 导致最后一行被裁剪。此前“只隐藏滚动条”的实现仍可滚动，未满足完整概要要求。

## 修改

- 去掉概要的固定 640 pt 上限，依据实际显示行和平台显示开关计算完整高度。菜单栏浮窗与独立窗口共用计算；显示开关及账号增删可更新外框，服务导航保持高度稳定。
- 概要能完整放下时直接排列卡片，不创建 ScrollView。平台详情仍有独立内容滚动容器。
- 详情所需高度仍以 640 pt 为常规基线，较长概要可以增高整个外框。保留 440 pt 宽、字号、卡片、额度图示和底部操作。
- 最终限制仅来自当前屏幕的可用高度。若内容确实超过物理屏幕，保留内容滚动兜底，不将更多账号裁剪或放到屏幕外；不能保证无限账号在任意屏幕无滚动。
- 没有修改登录、凭证、刷新、点火或计划，不新增服务请求。

`UsagePanelView.swift`、`SharedQuotaViews.swift`、`StatusItemController.swift`、`DetailPanelLayoutTests.swift`。使用七个示例账号验证高度 684 pt、完整概要无滚动容器、导航稳定及 600 pt 短屏降级；既有四种显示组合改为验证概要无滚动，另留详情滚动断言。

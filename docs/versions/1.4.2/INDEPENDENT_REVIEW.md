## 待核验的关键路径

- 同一 Profile 的完整读取、确认读取、唤醒探测共享进行中结果；不得把忙碌当作失败或缓存命中。
- 等待者持有对应轮次结果，不能收到后续轮次结果；停止和连接替换不会造成死锁或泄漏。
- 手动刷新合并一次补刷，按钮在进行中仍可请求；停止后不启动补刷。
- 自动退避 30/60/120/300 秒实际接入调度器，而不只是服务层拒绝请求的阈值。
- 身份查询 3 秒、握手 5 秒、额度查询 15 秒；身份失败不阻止额度读取。
- 旧身份仅在同一连接内作为上次确认显示；重新建连、退出登录和账号变化使旧身份失效。
- 点火后共享查询必须确实发生于请求完成后，不能把请求前已开始的读取当作点火后的证据。
- 退出码仅反映模型请求执行失败；窗口观测不是模型请求失败，也不是窗口开启的因果证明。
- Python 查询覆盖分包、粘包、通知穿插、总期限和自有进程组回收。
- 外部安装检测意外改动、备份并可回滚，保持 plist 内容及加载状态不变。

## 实施中预审（2026-09-23 12:26，待最终差异复核）

以下基于尚未完成的实现，不表示最终缺陷清单；实施完成后必须逐项复核：

- `probeRateLimitsAfterWake` 在空闲分支直接读取现有 client，却没有占用 `operationRunning`，可与随后开始的完整查询并发；失败还可能关闭另一轮正在使用的连接。
- `performShared` 仅在 `currentKind` 为 `.full` 时执行手动补刷；如果手动调用加入 `.rateLimitsOnly`，等待者会被返回 shutdown，而没有真正停止。
- 结果分发后先解锁、再由 defer 清除 `operationRunning`，该间隙加入的等待者可能永远收不到结果；结束和关闭请求槽必须在同一锁区间完成。
- 点火确认当前可加入点火前已开始的查询，需要观测开始时间或明确的查询屏障来排除旧证据。
- 此时尚未看到自动退避期限接入调度、按钮补刷和对应测试；等待实施完成后核对。

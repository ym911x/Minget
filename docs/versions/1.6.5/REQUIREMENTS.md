# 1.6.5 需求：概览显示 Command Code 月额度、各品牌详情页单独刷新

用户提出两点：

1. Command Code 的额度在概览里只显示 5 小时窗口，看不到周额度或月额度；用户观察到 5 小时上限的两倍正好等于周上限，因此提出可以直接显示月额度而不必显示周额度，并征求建议。
2. 每个品牌的详情页各增加一个刷新按钮，只刷新当前点开的那个品牌，不刷新其他品牌；按钮位置与样式由实现方确定。

## 建议与结论（依据真实数据）

实现前从本机应用自身的业务缓存（`local.usagemonitor.UsageMonitor.plist`，只读，非凭证）核对了 Command Code 账号的真实窗口，确认服务端同时返回三个窗口：

公开资料只记录结构与选择依据：本机该账号的 5 小时、周和月度剩余均可读；本次观察中周上限是 5 小时上限的两倍。月度剩余来自 credits，月度上限沿用详情卡由本月已用与剩余相加的规则。个人用量和余额明细不公开，此观察不推广为所有套餐的规则。

- 用户的观察成立：周上限正好是 5 小时上限的两倍，本轮采纳月度剩余作为概览第二列，不据此推定其他套餐的窗口关系。
- 月度剩余是决定本月预算的数字，因此采纳用户建议：**概览的 Command Code 行显示 `5H` 与 `月` 两列金额，不显示周额度**。
- 周额度继续保留在 Command Code 详情卡的三行窗口里，详情卡本轮不改。
- 兜底：月度剩余确实未读到（辅助接口不可用且 credits 未返回 `monthlyCredits`）时第二列退回 `周`；两者都没有时保持现有单列 5H 布局，不显示空框、不补零。

## 概览

- Command Code 概览行的额度图示由单列 `5H` 改为两列：`5H` 与 `月`，均为 `$余额 / $总计` 金额、紫色额度轨和靛蓝时间轨；月度时间轨使用连续模型并沿用计费周期起止时间。
- 两列各 4 pt 额度轨与 3 pt 时间轨，列间距 12 pt，行高 64 pt 不变；金额仍为服务端原值，不做百分比换算。
- 缓存的辅助数据（月度上限来自缓存的统计、周期来自缓存的套餐）按详情卡同样口径标橙色；行整体缓存语义不变。
- 悬停与无障碍文本同时包含两个窗口的金额和时间信息。
- 不改详情卡的三行窗口结构、不改菜单栏、不改拖动排序。

## 各品牌详情页单独刷新

- 服务标签行（概览 / ChatGPT / Gemini / DeepSeek / Command Code）最右侧新增刷新按钮，仅在品牌标签（非「概览」）且该品牌存在可刷新账号时出现。
- 点击只刷新当前品牌：
  - ChatGPT：只跑两个 ChatGPT Profile 的那一个刷新周期；
  - Gemini：只刷新 Google / Antigravity 的本机连接；
  - DeepSeek：只刷新 DeepSeek 连接的余额，并强制刷新该页的公开服务状态；
  - Command Code：只刷新 Command Code 连接，强制三路（credits、summary、subscriptions）。
- 手动刷新路径绕过节流与失败退避，与页头全局刷新同级；不新增任何网络请求类型。
- 按钮沿用卡片内既有按钮样式（bordered、small、24 pt 高），刷新中显示进度指示并禁用。
- 页头右上角的全局刷新按钮行为不变，仍刷新全部来源；「概览」标签下不显示品牌刷新按钮。

## 边界

- 本轮为小版本迭代，只完成编码、自动验证、签名构建与本机安装；不发标签、不推送远端、不建 Release，除非用户明确要求。
- 不读取认证文件、不读取浏览器会话、不向第三方发送凭证；不新增端点，不改变取数与节流口径。

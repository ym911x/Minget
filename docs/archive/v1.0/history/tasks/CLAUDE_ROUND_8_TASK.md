# 第八轮修订：优先打通智谱控制台余额读取

## 用户最新要求

“如果确定 API 这条路走不通就把它去掉，不要再有智谱 API 的相关配置了，专注把另一条路走通。”

本任务覆盖第七轮任务中继续扩展 API Key 路线的安排。ClaudeCode 负责编码，Codex 审核。先读 AGENTS.md 和 REVIEW.md 第七轮审核。

## 执行方向

1. 控制台登录与余额读取是本轮主任务。不要为了 API 路线反复搜索、猜端点、猜认证头、要求用户重复输入 Key，或拖延控制台修复。
2. 对 API 路线只做有边界的证据核查。HTTP 200、顶层 code/data/msg/success、合成测试、第三方项目声明均不能单独证明可用或不可用；单把 Key 被拒绝也不能证明整条路线不可用。现有证据不足时明确写“未证实”，不要伪造否定结论。没有可用证据时直接继续控制台工作。
3. 若确证该 API Key 路线不支持所需余额查询，删除智谱 API Key 输入、保存、探测和自动回退路径及相关配置说明；迁移后不得再读取或使用旧 GLM Key。如需清除本应用持有的旧条目，只针对本应用的 glm.api-key，不能读取凭证值或动 DeepSeek 凭证。保留有意义的回归测试，删除已撤销功能的专属测试并解释测试数变化。

## 控制台路径必须完成

- 只使用用户在本应用自建 WKWebView 内主动登录产生的会话，不读取其他浏览器数据。
- 核实登录后控制台实际显示余额的页面及其数据来源。优先复用该窗口合法产生的会话读取官方只读余额资源；若余额请求依赖的认证机制与当前 Cookie-only 实现不同，按实际观察适配，不能把登录成功等同于余额读取成功。
- 若适合直接读取应用自建 WebView 中的余额 DOM，则采用确定性的标签与字段匹配，并验证单位和金额语义。不得用模型识图、OCR 猜余额，不调用模型接口。
- 原始凭据与网络响应不进入终端、日志、报告或模型上下文；诊断限固定状态、脱敏结构和字段类型。若需要用户重新登录，在应用内提示，不让用户向聊天发送 Key 或 Cookie。
- 修复会话选择持久性：重启后继续使用已选控制台连接，不自动切回旧 API Key。任何余额缓存必须归属于实际使用的会话/账户；重新登录或更换会话不得显示旧账户缓存。
- 区分未登录、登录过期、读取失败、结构不支持、成功获取；只有成功解析金额时显示已连接。认证失败停止自动重试，重新登录后恢复。
- 修复 REVIEW.md 中金额语义和 null 问题：可用余额不能伪装总额；存在但为 null 的已声明金额字段按严格合同处理，不用其他字段掩盖未知值。
- 保留保存反馈和焦点修复。成功连接后关闭登录窗口，主面板显示余额与更新时间。输入框稳定性需要实际 UI 验证，状态测试不等同于 UI 验证。

2. 运行 swift test 与 scripts/build.sh，记录真实结果；不得用合成响应冒充真实 GLM 验收。
3. 更新 PROVIDER_ENDPOINTS.md 并生成 ROUND_8_REPORT.md，分别列出已实现、自动测试、实机验证和仍缺证据。最终验收需要同一账户控制台与小组件的余额、单位、语义一致。
4. 不提交、不推送、不改全局配置。完成可独立推进的实现、测试和构建后报告；确需用户在应用内登录时准确说明阻点。

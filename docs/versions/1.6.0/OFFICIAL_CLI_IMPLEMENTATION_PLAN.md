## 1. 执行目标与范围

将昨日的 CLIProxyAPI 原型切换为 Google 官方 Antigravity CLI：Minget 提供两个账号的登录入口，官方 CLI 完成官方浏览器授权并保管认证资料，Minget 调用内置 `/usage` 读取真实额度。用户已经接受官方 CLI 依赖，不需要 CLIProxyAPI、Google GUI 应用或第三方插件。

用户体验：首次使用或没有可用连接时能看到登录入口；已有连接日常启动显示额度。账号 A、B 独立登录、改显示名、重新登录和断开。在另一台 Mac 安装 Minget 后，通过引导准备官方 CLI，分别登录两个账号即可使用，无需复制认证文件。

展示官方返回的共享额度组、5 小时和周剩余比例、重置时间。保留现有卡片、菜单栏来源选择、五分钟自动刷新、手动刷新和唤醒补刷。已登录与额度读取成功是两个独立状态。

本轮不创建 Minget 自有 Google OAuth 客户端，不直接调用 Google 内部 HTTP 额度接口，不恢复代理方案，不发起模型请求，不推送远端或公开发布。原自有 OAuth 方案的测试模式七天到期问题，不直接套用于官方 CLI 授权；官方 CLI 的真实续期行为另行验证。

## 4. 技术方案与模块边界

目标数据流：

```text
账号管理窗口（A / B）
  → Google 账号状态模型
    → 官方 CLI 登录服务 / 只读额度服务
      → 每账号独立的子进程环境与持久目录
        → Google 官方授权和官方额度服务
    → 严格 JSON 解析 → 归属校验 → 独立缓存 → 卡片 / 菜单栏
```

建议模块名称可随现有风格调整，职责必须保留：

| 模块 | 职责 |
| --- | --- |
| `AntigravityCLILocator` | 查找或准备官方可执行文件，验证架构、版本、签名和兼容性 |
| `AntigravityProfileStore` | 管理 A/B 槽位、连接 UUID、独立目录及非敏感身份元数据 |
| `AntigravityProcessRunner` | 固定参数启动、最小环境、输出上限、总超时、取消与自有进程组回收 |
| `AntigravityLoginService` | 用户主动启动的交互登录、官方身份确认、一次性授权码输入、取消 |
| `AntigravityCLIUsageService` | 已连接账号的固定 `/usage` 查询、错误分类和版本约束 |
| `AntigravityCLIReport` | 已存在；将官方 JSON 转成额度组，继续严格解析 |
| `AntigravityModel` | 两账号独立状态、刷新调度、连接代次、重复账号检查和缓存 |

服务通过协议注入，进程运行、时钟、目录和缓存应可替换以测试。不要让 SwiftUI 直接启动进程，不复用代理的 `authIndex` 作为 CLI 身份。

### 4.1 身份、连接与状态

- 槽位 A/B 是 UI 位置；账号身份来自官方认证界面或经过验证的官方输出；连接 UUID 是每次连接的本机实例。三者不得混用。
- 优先调查官方是否提供机器可读稳定账号 ID；目前只有真实邮箱已观察到。若只能取得官方邮箱，使用规范化邮箱作为本版本身份键并明确记录限制，不能宣称取得 Google sub。不得通过删除邮箱点号、加号等猜测归并账号。
- 显示名称由用户修改，不影响身份。无法确认身份时不发布该槽位的额度为已验证账号数据。
- 认证状态至少区分：未连接、登录中、已连接、需要重新登录。
- 读取状态至少区分：未读取、读取中、成功、缓存过期、网络失败、限流、接口/CLI 不兼容或无权限。
- 配额查询失败不一律归为未登录。一个账号授权失效不能暂停另一个账号。

### 4.2 存储与凭证边界

- 正式目录使用本机 Application Support 下的 Minget 专属目录，每个连接 UUID 使用独立 profile，权限限制为当前用户；具体路径集中定义并校验。
- 同时隔离子进程 `HOME` 与 `ANTIGRAVITY_APP_DATA_DIR`；只修改子进程环境，不修改用户全局环境或 shell 配置。
- 官方 CLI 自行存储凭证。Minget 不打开、解析、复制其认证文件，不抓取浏览器会话，不自行提取或转存 OAuth token。
- 不能承诺官方 CLI 所有凭证都在 Keychain；其具体存储机制尚未确认。原“所有 Google token 由 Minget Keychain 保存”的要求按本路线修订。
- Minget 只持久化必要的非敏感账号元数据、连接 UUID、显示名、规范化额度和抓取时间。一次性授权码仅在内存中短暂传递，不进入日志、偏好、崩溃附件或测试快照。
- `/tmp/minget-agy-probe` 是试验环境，不能成为正式依赖。正式目录通过官方流程重新登录；不自动复制临时认证文件。需要用户操作时解释这是正式持久环境的首次连接。

## 5. 分阶段实施与门槛

### P0：解决交互与后台运行边界，先提交可审查的探测结果

在空工作目录和 Minget 自有环境内，对已验证官方 CLI 做最小探测：

1. **身份读取**：找到官方支持的身份输出；没有机器接口时，验证受控 PTY 能稳定获取官方登录后的账号邮箱。明确 ANSI、分块输出、不同终端宽度和提示变更处理。解析失败即停止账号提交，不用用户自填邮箱代替官方证据。
2. **登录协议**：验证如何从应用启动官方浏览器、将用户输入的一次性授权码交给等待中的 CLI，以及登录成功、拒绝、取消和总超时如何识别。自动回调只有实际验证后才能实现为默认；至少提供真实可用的手动授权码输入。
3. **首次引导**：处理官方主题、服务条款、可选数据收集和空目录信任提示。让用户看见并选择相关条款，默认关闭可选数据收集。不对将来变更的条款盲目自动确认。此前用户对本次试验的同意不等于所有新用户的同意。
4. **后台无交互**：寻找官方明确支持并实际验证的非交互或禁止自动浏览器机制，覆盖未登录与授权失效。已试验的 `AGY_CLI_NONINTERACTIVE_HEADLESS=1` 没有证明可以阻止浏览器；`SSH_CONNECTION` 伪装也不是已验证方案。不能把这些假设作为实现依据。
5. **超时和回收**：进程外的总超时必须覆盖授权、启动及查询全流程；`--print-timeout` 不能替代它。验证取消后只回收自有子进程与其后代，不遗留监听和 PTY，不使用全局 `killall`。
6. **版本与更新**：确认版本检测以及固定内置命令分发；验证 `AGY_CLI_DISABLE_AUTO_UPDATE` 是否实际有效，不将字符串存在视为行为保证。

退出条件：记录每项的命令、CLI 版本、脱敏结果、已通过/未通过及可实现接口。身份和后台无交互均通过后才正式切换常驻自动刷新。

若官方 CLI 无法提供安全可用的后台行为，停止相关生产切换，明确报告具体限制；可以继续实现独立可完成模块和用户主动登录/读取原型，但不能将手动模式当作全部需求已完成，也不能悄悄退回代理或自有 token 调用。

### P1：官方 CLI 准备与持久账号环境

- 优先识别经过校验的官方 CLI；缺失时显示清楚的安装/下载引导。实现官方来源下载时先检查当前官方安装说明与清单，不直接执行未经检查的 `curl | bash`。
- 试验基线是 1.2.13、arm64。其他架构必须匹配官方包并实际验证；未验证的平台不标记支持。
- 下载到暂存目录，验证官方清单校验和、Google 签名及架构后再原子启用。失败保留旧可用版本；安装取消可恢复。
- 建立明确的已验证版本范围；未知或不兼容版本提示升级/兼容性问题，禁止把 `/usage` 降级为模型提示词。
- 未核实再分发条件前，不把官方二进制直接打包进 Minget 分发；使用官方安装或下载路径。
- 创建正式 profile 和空工作目录，不扫描现有用户配置、项目或全局 Google 登录状态。每个 profile 同时仅允许一个修改认证状态的操作。

### P2：登录、重新登录、重复账号与断开

- 在既有账号管理窗口提供 A/B 两个入口：登录、取消、重新登录、编辑显示名称、断开本机连接。
- 登录使用待提交的新 profile，确认官方身份后再原子绑定槽位。若身份已被另一槽位占用，提示重复连接，保留已有账号，不覆盖另一槽位。
- 重新登录采用相同事务流程；失败或取消不错误覆盖原身份。登录成不同账号应明确作为更换账号处理，旧额度不得继承。
- 登录成功即可显示“已登录”；随后独立读取额度，读取失败展示实际失败原因。
- 登录进行中暂停该 profile 的查询，避免登录与刷新竞争；另一账号正常运行。
- 断开先增加连接代次、取消相关任务，再清空该连接的缓存和元数据。旧任务迟到的结果必须丢弃。
- 不调用未经验证的全局 `/logout`，不按猜测批量删 Keychain，不撤销影响其他 Mac 的授权。只有验证 profile 范围的清理方式后，才删除该连接的本机凭证；只允许操作精确校验的 Minget 自有目录。
- 若无法安全清除 CLI 管理的本机凭证，明确保留为未完成门槛，不能把仅隐藏槽位称作已清除凭证。

### P3：只读查询与解析

基线固定命令（实际执行用绝对 executable URL 与参数数组，不经 shell 拼接）：

```sh
agy --log-file /dev/null --print /usage --output-format json --print-timeout 20s
```

- 仅对已验证连接的 profile 运行；使用受控最小环境和空工作目录。
- 分别收集 stdout/stderr，限制大小；登录与查询输出不原样写入日志。错误只保存经过归类和脱敏的诊断。
- `AntigravityCLIReport` 已实现 1 MiB 上限、成功状态、内置命令身份、零轮次/token、重复标识检查。保持这些约束，并补充进程退出状态和总超时处理。
- 使用 `command.data.groups`，组名作为当前官方组标识；桶按官方 `id` 区分。若未来获得稳定组 ID，做显式缓存迁移。
- `remaining_fraction` 必须是有限的 0…1 数值；缺失、布尔值、非法值显示未知，真实 0 显示耗尽。保留原精度，显示层格式化。
- 周期只按实际 `window`；不从名称猜出缺失的 5h/weekly。未知周期可以按官方名称展示，但不填入五小时/周位置。
- 重置时间只读取官方时间；非法或缺失显示未知，过期只触发受控补刷，不自动补成 100%。
- 不把共享组拆成单模型额度；不把描述性文本当稳定的模型数组。
- 区分网络失败、授权失效、无权限、CLI 不兼容和限流。有官方重试时间则尊重它，否则使用有上限退避；不要伪造 HTTP 状态。

### P4：刷新、缓存与界面接线

- 重写 `AntigravityModel` 的代理发现流程，改为两个独立连接，每个连接独立任务、失败状态、上次尝试时间与退避。
- 每次查询捕获连接 UUID、身份和 generation；完成时再次校验三者及当前连接状态后才发布和写缓存。
- 缓存键含数据源版本、身份和连接 UUID；启动加载只接受完整匹配。旧代理快照不能按 A/B 下标自动转成 CLI 快照。
- 同账号请求串行或合并，双账号可以并发；刷新中的手动请求最多合并为一次跟随查询，避免重复启动。
- 沿用五分钟自动刷新、手动刷新与唤醒补刷，维持合理节流。授权失效暂停该账号自动查询，显示重新登录入口，后台不弹浏览器。
- 有缓存时明确显示更新时间及缓存/失败状态，不能将旧数据标为实时；无缓存时显示未知或空状态。
- 全新安装展示连接页；已有其他平台配置的用户进入 Google 功能时可见 A/B 登录入口。日常启动已有有效连接时显示额度，不每次强制登录。
- 菜单栏偏好绑定账号身份和组标识。所选账号断开或组消失时显示不可用并允许重新选择，不静默改成另一个账号。

### P5：移除代理运行依赖与迁移

- 移除地址、管理密钥表单、账号发现、代理转发和代理生产实例化；界面不再提示启动 CLIProxyAPI。
- 将通用额度数据模型从代理实现中解耦，保留可用的卡片与显示逻辑。
- 正式切换时清理 Minget 自己的旧代理偏好、快照及 `.antigravityManagementKey` 对应 Keychain 项；采用可重试、幂等迁移，失败不误删其他平台凭证。
- 不触碰 CLIProxyAPI 本身的文件、认证资料、进程或其他应用数据。
- 检查打包脚本内 Info.plist 说明和 Resources/README.txt，目前仍写着代理认证，必须同步修正。
- 更新项目凭证边界，明确允许官方 CLI 在 Minget 自建隔离环境中管理授权，同时保留禁止直接读取认证文件的规则。

## 8. 真实验收矩阵

1. **本机两账号**：正式持久目录分别登录；从官方界面确认身份；同一时间段比对两账号各额度组的 5h/weekly 比例与重置时间，记录时区和查询时间差。
2. **重启与并发**：退出重开 Minget、退出重开 CLI、A/B 并发读数，确认没有串号；不读取认证文件来证明归属。
3. **异常恢复**：网络断开恢复、CLI 缺失/不兼容、取消和超时、真实授权失效/续期可观察场景。无法当场验证的续期标记待验证，不用模型请求或重置额度制造事件。
4. **断开与重复**：B 登录 A 时拒绝覆盖；断开 A 后 A 旧请求不回写，B 不受影响；重新连接恢复。
5. **第二台 Mac**：初始无代理、官方 CLI 和 Antigravity GUI；通过产品引导准备官方 CLI，完成首次启动、两账号登录、额度读取、退出重开和重新登录。不能复制第一台认证文件。
6. **跨电脑独立性**：第二台断开一个账号后，第一台对应连接仍可读取；验证本机断开不会全局撤销授权。
7. **零模型调用**：实际查询保持内置 usage 与零轮次/token。不得用模型请求测试权限或耗尽额度。

需要用户进行登录、设备操作时只请求必要操作；没有第二台设备就清楚标记跨 Mac 验收未完成，不能用本机双 profile 替代。

## 9. 构建、备份和交付

当前 `scripts/build.sh` 默认会安装到 `~/Applications/Minget.app`，不是纯编译脚本。开发验证先使用隔离的运行和归档路径，避免覆盖用户正在使用的昨日原型。

可使用以下候选构建命令；执行前检查各路径不存在需保留内容：

```sh
MINGET_BUILD_SCRATCH_DIR=/tmp/minget-google-build \
MINGET_STAGING_DIR=/tmp/minget-google-candidate/staging/Minget.app \
MINGET_RUN_PATH=/tmp/minget-google-candidate/run/Minget.app \
MINGET_ARCHIVE_PATH=/tmp/minget-google-candidate/archive/Minget.app \
scripts/build.sh
```

沿用已有 `Minget Local Signing` 身份，不无故改为 ad-hoc；脚本负责严格签名验证。候选构建可以用于真实验收，不等于完成正式交付。

全部必需门槛通过后：备份当前安装的 Minget 到带时间戳的本机目录，保留可恢复路径，再构建/安装签名版并复核运行。若项目没有现成安装包格式，不虚称产生 DMG/PKG；明确实际交付的是已签名 `.app` 及现有支持的归档形式。本地签名也不等于 Apple 公证或跨 Mac 信任已通过。

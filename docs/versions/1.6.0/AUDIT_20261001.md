## 为什么 OpenAI 方案已成功，Google 仍未交付

共同思路是应用提供入口、官方 CLI 管理授权、每个账号独立环境、只读额度。具体接口不同：

- Minget 的 Codex 实现使用 `account/login/start` 返回 URL/loginId，官方 app-server 接收回调并发送 `account/login/completed`；`account/read` 取得身份，`account/rateLimits/read` 取得额度。代码和[官方说明](https://learn.chatgpt.com/docs/app-server)一致。
- 当前已验证的 Antigravity CLI 1.2.13 通过官方浏览器及授权码回填完成登录，官方交互屏幕确认身份；额度 JSON 无账号身份。没有查到与 Codex 等价的已验证登录/身份 RPC，不能原样套接。

9 月 30 日上午用户已经完成两个试验账号登录。随后实施记录在约 21:09 明确因空账号后台等待、更新子进程及身份集成问题暂停。这个暂停记录没有把用户操作缺失列为原因。

23 点后代码增加了系统沙箱和认证提示识别，以及通过专用参数打开的试验窗口。这些能力尚未形成正式 UI 与服务接线，且尚无正式登录完成记录。

## 最新代码检查发现的问题

### 1. 授权码提交后不能继续官方引导

`AntigravityLoginSession.swift`：

- `navigate` 第 25 行要求 `!codeSubmitted && !authenticationReady`。
- 提交授权码后，第 35 行将 `codeSubmitted` 设为 true。
- 第 91 行在提交后将实际屏幕替换为固定“等待官方身份确认”文字。

`AntigravityLoginView.swift` 第 17 行只在认证 URL 为空时显示选择按钮；URL 到最终成功/失败前没有清除。假如授权后 CLI 继续展示条款、数据选择或目录信任，当前实现会隐藏提示并阻止操作，可能直到 300 秒总超时。

这是静态代码确认的交互缺口；不能断言它就是上一次实际停住的画面。应改为明确的登录阶段状态机，既不回显授权码，也允许用户看见并处理授权后的官方引导。

### 2. 登录窗口没有正式接线

`UsageMonitorApp.swift` 第 88 行仅在 `--google-login-a` / `--google-login-b` 参数下打开试验窗口，然后跳过正常启动。第 92 行完成回调为空。正常 `AppContainer` 第 40 行依然实例化代理 `AntigravityModel`。

`AntigravityConnectionView` 依然是“本机代理地址 + 管理密钥”。当前没有把 `AntigravityCLIProcess` 或 `AntigravityProfileStore` 接入正常 Google 刷新链路。

### 3. 后台处理已有改善，旧门槛结论需重新核验

最新代码设置 `AGY_CLI_DISABLE_AUTO_UPDATE=true`、`AGY_CLI_NONINTERACTIVE_HEADLESS=true`，通过系统沙箱拒绝 fork、Apple Events 和相关 LaunchServices 查找；检测 stderr 的 `Authentication required.` 后终止进程。

本次按源码相同沙箱、环境及固定 `/usage` 参数，在新的空临时环境做探测：约 0.66 秒识别认证提示，主动终止并回收自有进程，删除本次临时目录；未生成模型请求。未输出或保存授权 URL/授权码。

该结果证明当前配置能启动并快速识别这个认证场景；没有证明 CLI 自己不等待授权，也没有替代真实失效、完整登录、所有 updater 生命周期与系统版本兼容性验收。不能继续机械沿用早期“只能卡住”的结论，也不能据此直接宣告 P0 全通过。

Google [Headless 文档](https://antigravity.google/docs/cli/headless/)说明非交互环境未认证应直接报错。早期 1.2.13 实测与此有差异，Minget 仍需以实际生命周期控制为依据。

### 4. appdata 参数与真实启动环境不一致

`AntigravityCLIProcess` 接收/检查绝对 `appData`，但实际启动使用 `ANTIGRAVITY_APP_DATA_DIR=appdata`，未使用该参数。相对路径与工作目录有关，和最初验证使用的每账号绝对 appdata 不一致。现有测试只比较 basename，未验证实际路径归属。正式接线前应统一并重新验证登录和查询使用同一目录。

# 1.2.0 审核状态

## 当前结论

本地实现审查完成。代码只向固定主机发起三条 GET 请求，使用 Keychain 读取的 API Key；没有 Command Code CLI、认证文件或浏览器数据读取路径。2026-09-15 的 `swift test` 通过 309 项，`./scripts/build.sh` 的 1.2.0 安装包严格签名校验通过。用户截图确认真实接口能返回额度和统计字段；尚未与 Studio 同时对账的字段含义继续保持待确认。

## 已检查

- `CommandCodeProvider` 使用精确路径集合，默认 JSON Accept 和每次请求 Bearer 认证。
- `ProviderRequestGuard` 永久阻断生成、chat completions 和 messages 路径，生产 URLSession 拒绝跨域重定向。
- 缓存、报告和 UI 以可选用量字段兼容旧 DeepSeek 缓存；缺失数据不变成零。
- 详情页无滚动容器并覆盖四种卡片组合高度。
- 修复刷新完成后的报告重建遗漏 `usage` 缓存字段的问题。此前成功响应可短暂显示，随后 `allReports()` 重新发布时会把 Command Code 卡片回退为空状态；回归测试固定成功数据在重新发布后仍存在。
- 进一步把刚成功读取的 `usage` 保存在刷新引擎进程内状态。即使重启恢复用的缓存读失败，当前进程的重新发布也不再抹去刚显示的数据。

## 待验收

- 用户在正式构建中主动输入真实 Key 后，记录脱敏状态码与字段名，并与 Studio 同时核对额度、token、请求、成本和统计周期。
- 检查正常启动、手动刷新、五分钟自动刷新和完整重启；确认没有重复 Keychain 提示或模型请求。
- 在真实账号验收时确认官方 Logomark 在浅色与深色系统外观下的实际显示。

# v1.5.0 实施记录

已在独立工作树实现 v1.5.0，版本号更新为 1.5.0。没有修改冻结的 `docs/archive/v1.0/`，没有推送或发布。

修改范围：

- `DetailPreferences`、`UsagePanelView`、`MingetSettingsView`：持久化两种显示模式和当前标签，按稳定供应商标识筛选，固定底部操作区，短屏仅滚动卡片；切换不调用刷新。
- `StatusItemController`：菜单栏重复点击关闭浮窗，切换标签时调整浮窗高度，复用设置和账号窗口。独立详情窗口沿用现有备用入口。
- `FirstRunGate`、`AccountManagementView`、`UsageMonitorApp`：新安装显示一次可跳过连接界面，已有本应用偏好或缓存的升级用户不强制引导。
- `CodexAppServerClient`、`UsageService`、`UsageViewModel`：官方 ChatGPT 浏览器登录 RPC、取消与完成通知；单个交互登录，匹配登录 ID 和连接代次，登录时暂停相应账号的额度读取，完成后使用现有刷新引擎读取身份和额度。
- `README.md`、`ROADMAP.md`、`PROVIDER_ENDPOINTS.md` 和本目录：版本说明及接口依据。

验证：`swift test --disable-sandbox` 完整通过（Core 395 项，App 162 项，其中 1 项原有辅助功能测试跳过）；新增的早到登录通知、筛选高度测试通过。最终 Release 构建由 `scripts/build.sh` 完成，`codesign --verify --deep --strict` 对暂存包和已安装包均通过。已备份原 1.4.3 安装包，最终 1.5.0 安装于 `/Users/yuyimeng/Applications/Minget.app`。签名包启动后观察到两个隔离 app-server 子进程；发送 SIGTERM 后主进程及两个子进程均退出，随后重新启动。

验收边界：Mac 已解锁，本应用偏好中的两个隔离账号额度缓存时间戳在签名版运行期间更新，证明既有连接的真实只读取数成功。当前桌面自动化无法直接定位无窗口的菜单栏图标，菜单栏点击、Esc、窗口切换等真实界面操作仍待验收。真实 ChatGPT 首次浏览器授权、DeepSeek/Command Code Keychain 提示和第二台 Mac 首次使用也尚无本版实测证据。模拟 RPC、静态渲染和进程检查不能替代这些验收。不记录真实凭证或授权 URL。

签名版真实截图显示详情四张卡片与固定底部入口，且暴露 Command Code 成功率显示过长小数。已将该字段的展示精度限制为最多两位小数，并增加断言。修复后完整测试再次通过（Core 395 项，App 162 项，其中 1 项跳过），Release 包重新构建、严格签名并安装。并行构建时曾有一项既有进程超时测试未等到 PID 文件；构建结束后顺序重跑完整测试通过。截图含私人账号及额度，不复制入仓库。

真实设置窗口验证了模式保存；独立详情窗口验证了四个标签、单一供应商高度变化、ChatGPT 两账号同组以及“详情 → 账号管理 → 详情 → 设置”流转。用户确认旧签名包的菜单栏第二次点击仍会保留详情浮窗，而 Esc 与切换窗口可关闭。为避免系统 `.transient` 在鼠标按下时先关窗、按钮鼠标抬起又重新打开，浮窗改为应用主动管理关闭；外部点击、Esc、应用失焦分别由监听器处理。账号管理把已有成功读取但当前显示缓存的状态改为“上次额度可用”，并显示供应商和用户自定义账号名。此次改动后完整测试通过（Core 395 项、App 162 项，1 项跳过），Release 包严格签名并重装；菜单栏连续点击仍需用户在新签名包复验。

用户随后报告：改为主动管理后，连续点击几十次仍有数次未关闭；进一步改为鼠标按下即切换、按同一事件编号去重后，用户报告仍经常需要再点一次。检查用户真实截图与命中代码后，发现浮窗箭头可进入菜单栏按钮区域，而旧矩形判断优先归属浮窗，导致按钮被箭头遮住时监听器也不关闭。现改为重叠区域优先归属实际状态按钮，保留纯几何和事件去重回归测试。完整 `swift test --scratch-path /tmp/minget-150-swiftpm-tests` 通过（Core 395 项、App 163 项，1 项原有 AX 环境跳过）；Release 构建与严格签名通过，已安装新签名包。诊断版仅在显式设置 `USAGE_MONITOR_LOG_FILE` 时将事件类别、编号和浮窗状态写入本机临时文件，未记录账号、额度或凭证。重叠修复尚待用户连续点击复验，不以自动测试代替真实交互。

用户再次报告重叠修复版失败。本地诊断记录在同一次点击中依次出现“全局监听关闭 → 浮窗已关闭 → 按钮动作看到未显示 → 再打开”。部分点击被全局监听误判为外部点击；按钮动作的当前事件编号为 `0`，此前编号去重无效。因此移除全局鼠标监听，改由按钮动作独立切换浮窗，本应用内外部点击与箭头重叠区由本地监听处理，其他应用点击由应用失焦监听处理。移除无效去重代码及测试后，完整 `swift test --scratch-path /tmp/minget-150-swiftpm-tests` 再次通过（App 162 项，1 项跳过；Core 测试通过）；Release 包重新构建、严格签名并安装，真实重复点击和外部点击待用户复验。

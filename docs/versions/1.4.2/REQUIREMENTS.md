# 1.4.2 单飞刷新、退避与身份状态需求

状态：实现和自动化测试通过；签名安装、真实账号/界面、自然定时运行及 GitHub 发布状态见 ACCEPTANCE.md。本轮不改变账号绑定、缓存结构、点火命令、模型、时间表和网络接口。

## 1. 目标

- 同一 Profile 的完整读取、确认读取、唤醒探测、手动刷新共享一次"进行中"的结果：等待者拿到实际结果，而不是把忙碌当成失败或缓存命中。
- 瞬时失败走"立即重试一次 + 自动退避"的梯子：30/60/120/300 秒，封顶 300 秒；成功清零，手动重试旁路；退出登录、缺少 CLI 这类不可自动恢复的失败不进入重试循环。
- 身份显示区分"已确认 / 上次身份 / 不可用"三种状态，只允许在连接内保留上次身份，并以明确标签呈现。
- 每张卡片自带 fetching / live / cache / failure 与最近成功时间，头部不得暗示全部数据都是新鲜的。
- 点火结果继续区分"模型请求执行结果"与"重置时间观测"，未变化和不可观测都不是请求失败。
- 外部点火计划脚本提供可复现模板与显式安装器：干净日志、原子替换、可回滚、绝不触碰 launchd。

## 2. 单飞（shared single-flight）

### 2.1 共享槽

- 每个 Profile 的 `UsageService` 持有一个共享操作槽。任何时刻至多一个操作在运行：完整读取、确认读取、唤醒探测之一。
- 操作运行期间到达的调用者加入该操作并等待它的实际结果；不允许返回"忙碌"错误，也不允许把缓存当作本次结果返回给等待者。
- 等待者收到的必须是它加入的那一轮的结果；不允许把后续轮次的结果发给前一轮的等待者。

### 2.2 手动补刷

- 手动点击（`resetFailureBudget: true`）在操作进行中到达时，排队恰好一次补刷：该轮结束后由同一个执行者立即再跑一轮完整读取，排队者收到补刷轮的实际结果。
- 自动调用只合并（coalesce），不排补刷。
- 停止（`stop`）之后不启动补刷；补刷排队的等待者以 shutdown 错误释放。
- 结果分发与释放操作槽必须在同一个锁区间完成，避免"解锁之后、清理之前"到达的调用者成为无人唤醒的等待者。

### 2.3 唤醒探测占槽

- 唤醒探测必须占用共享槽：探测运行期间开始的完整读取加入探测，而不是与它并发使用同一个子进程。
- 探测失败关闭死连接是安全的，因为并发读取者此刻必然是等待者。
- 加入了一个无法产出实时读数的探测的完整读取，由同一个执行者立即补跑一轮真实读取，不得把探测的失败直接交给它。

## 3. 超时与重试

### 3.1 超时

- 额度查询（quota read）15 秒；握手（handshake）5 秒；身份查询（identity read）3 秒。
- 身份查询失败不阻止额度读取；额度成功而身份失败时，本连接的上次确认身份降级为"上次身份"而不是清空。

### 3.2 重试梯子

- 瞬时失败（超时、RPC 失败等可自动重试的错误）先立即重试一次；再失败则进入自动退避：30、60、120、300 秒，之后封顶 300 秒。
- 梯子必须可注入时钟并可查询下一次自动重试时间；成功清零；手动重试旁路门槛并重置梯子。
- 退出登录（`codexNotSignedIn`）、缺少 CLI（`codexCLINotFound`）、窗口不可用（`windowUnavailable`）不可自动重试：进入"需要手动重试"状态，不循环重启。
- 退避门槛接入调度器：自动刷新循环跳过门槛未到期的 Profile；确认读取随手动点火旁路门槛。
- UI timer 按最早仍可自动重试的 Profile deadline 缩短等待；其他 Profile 仍可按正常刷新周期独立更新。
- 停止与取消必须释放所有等待者，不等待卡死的操作（有界排空）。

## 4. 身份状态

- `confirmed`：本连接最近一次成功的身份读取确认的账号。
- `previous`（上次身份）：同一连接上，额度读取成功但身份读取失败，或额度读取瞬时失败时，保留的最后一次确认身份；卡片以"上次身份"标签明确呈现，不得当作仍然确认。
- `unavailable`：无可声明身份，显示"账号暂不可用"。
- "连接"指实际 app-server child 的连接代次。`connectionEpoch` 变化后旧身份清除；同一代次的身份临时读取失败可明确显示上次身份；新连接需再次确认，退出登录和已确认换号均清除旧身份；关闭不做任何声明。

## 5. 卡片状态

- 每张卡片独立显示 fetching / live / cache / failure 与最近一次成功时间；头部全局状态不得暗示所有卡片都是实时数据（有非 live 卡片时显示"部分数据未更新"）。
- 点火结果与观测分离：
  - `请求成功，重置时间前移`：观测到重置时间前进至少 60 秒（这是观测，不是新窗口开启的因果证明）；
  - `请求成功，重置时间未变化`：请求成功且两次只读观测均未见前进；
  - `请求成功，重置时间未知`：观测不可用（缓存回退、无 5 小时窗口等）。
- 点火后的确认读取保持只读（握手 + 额度），等待 2 秒、必要时再等 5 秒，绝不发第二次模型请求。
- 点火后的共享查询必须确实发生于请求完成之后：请求完成时间作为新鲜度屏障，屏障之前开始的读数不得作为点火后证据。

## 6. 外部点火计划脚本模板与安装器

- 基于 `~/.local/bin/minget-fire` 与 `~/.local/libexec/minget-fire/` 现有实现整理模板：严格串行 A → 15 秒 → B → 15 秒 → Command Code；单请求 120 秒超时；命令、模型、时间表保持不变。
- Python 读取器使用字节缓冲 `os.read` + 单一单调总期限，兼容分包与粘包 JSON；子进程以自有进程组启动并在退出时整组回收。
- 日志只使用固定字段：target / start / end / exit / duration / window / used / reset（含 drift 差值）；不记录子进程原始输出，不记录任何身份信息。
- 退出码只反映模型请求执行结果：请求成功时，观测未变化或不可用都退出 0；进程失败或超时退出非零（超时 124）。
- 安装器：预期哈希校验（SHA256SUMS）→ 时间戳备份并校验备份 → 临时文件 + 原子改名替换 → 打印回滚指令；绝不写 plist、绝不 `launchctl` 重载、绝不从构建产物自动安装。
- 假 CLI 测试覆盖：串行顺序、超时后续跑、聚合退出码、分包/粘包 JSON、总期限、进程组回收、观测退出语义、默认值与干净日志。

== 现象：staging 静默失败，dist/ 里留下 debug 构建 ==
本回合内多次执行 ./scripts/build.sh 与 ./scripts/build.sh --debug 后，最后一次默认构建输出为：
  == staging dist/Minget.app ==
  [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":56,"threshold":50,"scope":"turn",...}
  在受控环境里，rm -rf 因「单回合累计删除文件数超阈值」被拒。
  原脚本对此没有检查，随后继续 mkdir/cp，于是把 debug 构建的二进制留在了 dist/Minget.app，
  并以 exit=0 打印 built: dist/Minget.app。实测该包 CDHash=0173a4fc…（debug），而非 release 的 e4842fa1…。

== 修复：staging 后加存在性检查，失败即非零退出 ==
  rm -rf "$DIST/$APP_NAME.app"
  if [[ -e "$DIST/$APP_NAME.app" ]]; then echo error...; exit 1; fi

== 修复后的行为实测（同一回合，删除预算已耗尽）==
  ./scripts/build.sh 输出：
    == staging dist/Minget.app ==
    exit=1
  脚本在 staging 之前中止，未触碰已有产物。

  该事件属受控执行环境的安全限制，不是源码问题；但它暴露了 build.sh 的一个真实脆弱点：
  删除失败时脚本会产出「既不是上一版也不是新版」的混合包，并误报构建成功。现已 fail closed。

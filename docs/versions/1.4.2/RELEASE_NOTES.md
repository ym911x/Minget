# Minget 1.4.2 发布说明

## 概述

1.4.2 重构了每个账号的刷新调度与身份显示，并让外部点火计划脚本可复现、可回滚。刷新不再把"忙碌"当作失败：手动点击总是有回应，等待中的调用者拿到当轮实际结果；瞬时故障按"立即重试一次 + 自动退避"处理；账号卡片明确区分"已确认"与"上次身份"。

本版本改善本地客户端的协调、恢复与结果表述，不保证 OpenAI 每次都即时返回最新额度，也不会通过额外模型请求强制服务端推进或重置额度窗口。

## 刷新与调度

- 同一账号的完整刷新、确认读取、唤醒探测共享一次"进行中"的结果；等待者收到实际结果，不再收到忙碌错误或被误标为缓存的旧数据。
- 刷新进行中再次点击刷新不再被禁用：排队恰好一次补刷，补刷完成后自动继续。
- 瞬时失败先立即重试一次，再按 30/60/120/300 秒自动退避（封顶 300 秒）；成功即清零；退出登录、缺少 CLI 等不可自动恢复的问题停下等待手动重试，不会无限循环。
- 退出登录或连接失败期间，自动刷新尊重退避节奏，不再空转请求。
- 超时拆分：额度查询 15 秒、握手 5 秒、身份查询 3 秒；身份查询失败不影响额度数据。

## 账号身份显示

- 卡片身份区分三态：已确认（正常显示）、上次身份（橙色"上次身份"标签 + 邮箱）、账号暂不可用。
- 同一账号连接内的瞬时故障保留上次确认的身份并明确标注，不再静默重复旧邮箱，也不会因为一次读数失败就丢失账号显示。
- 退出登录、账号替换会让旧身份失效；确认读取永远不会错误地重新确认身份。

## 卡片状态

- 每张卡片自带获取中 / 实时 / 缓存 / 失败与最近成功时间；详情页头部在有卡片未实时更新时明确显示"部分数据未更新"，不再暗示全部数据都是新的。

## 点火（Command Code 计划）

- 点火结果与重置时间观测继续分离：请求成功但观测未变化或不可观测都不是请求失败。
- 点火后的确认保持只读（等待 2 秒、必要时 5 秒后各读一次），绝不发起第二次模型请求。
- 点火后的确认读数必须发生在请求完成之后，请求完成前已经开始的读数不作为点火后证据。

## 外部点火计划脚本（模板与安装器）

- `scripts/minget-fire/` 提供可复现模板：严格串行 A → 15 秒 → B → 15 秒 → Command Code，单请求 120 秒超时，命令、模型与时间表与现网一致；全部路径与时限可用 `MINGET_FIRE_*` 环境变量覆盖，便于测试。
- Python 读取器改为字节缓冲读取 + 单一总期限，兼容分包与粘包 JSON，子进程以自有进程组回收。
- 日志只记录固定字段（target/start/end/exit/duration/window/used/reset/drift），不记录子进程输出与任何身份信息。
- 请求成功时，观测未变化或不可用都退出 0；只有进程失败或超时（124）退出非零。
- `scripts/install-minget-fire.sh` 显式安装：SHA-256 预期哈希校验、时间戳备份、原子替换、打印回滚指令；绝不写 plist、绝不重载 launchd、绝不从构建产物自动安装。

## 兼容性

- 账号绑定、缓存结构、点火命令、模型、LaunchAgent 时间表与网络接口均未改变；无需迁移。
- 历史版本的审核与验收记录保持不变。

## 验证

- 自动测试：Core 380 项 + App 158 项，0 失败（1 项辅助功能环境跳过）。
- 外部脚本模板与安装器：53 项断言（假 CLI 沙盒，无网络、无模型请求）。
- Release arm64 严格签名构建与本机安装、外部脚本备份安装及安装后首个自然定时任务已核验；LaunchAgent 时间表未改变。
- 自然任务确认三路进程及 LaunchAgent 均 exit 0；A 的窗口观测不可用，B 重置时间未变化。该结果只验证请求/观测记录，不证明 OpenAI 窗口每次推进。
- 真实界面三次手动刷新已观察到数据返回；用户于 2026-09-24 确认详情页关闭重开三次均正常。第三轮聚合结束标志未单独留证，保留此证据边界。

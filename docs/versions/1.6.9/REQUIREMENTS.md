# 1.6.9 需求：刷新范围与频率优化

## 背景

当前（1.6.8）的取数以全量为主：ChatGPT 两个 Profile 按 30/60/120 秒自适应循环一起刷新，DeepSeek、Command Code 与 Gemini 按约 5 分钟循环一起刷新，启动时还会先全量刷一次；面板打开时再按 30 秒（ChatGPT）与 60 秒（Provider）的年龄门槛补刷。菜单栏同时只显示一个来源，其余账号的取数大多发生在用户没有查看的时刻，属于无谓请求。

1.4.0 的「低额度加速刷新」已经只作用于菜单栏选中的来源。本轮把默认刷新范围整体收窄到同一原则：显示什么刷什么，其余账号在打开页面时按 5 分钟门槛补刷一次。

## 需求

1. **默认只刷菜单栏来源**
   周期刷新（ChatGPT 自适应循环、Provider / Google 循环、启动首次刷新、唤醒补刷）只作用于菜单栏当前显示的那一个来源；其余账号没有任何后台周期刷新。

2. **打开页面补刷一次**
   点击菜单栏打开面板（独立详情窗口同规则）时，按当前显示的页面补刷：
   - 概览页：补刷未在菜单栏显示的账号（跨品牌）。
   - 品牌页（ChatGPT / Gemini / DeepSeek / Command Code）：补刷该品牌中未在菜单栏显示的账号。
   - 面板内切换标签与打开面板同等对待，切到哪个页面就按该页面判定。

3. **5 分钟门槛按整批判断**
   - 一个页面（概览或某品牌页）构成一个补刷批次。
   - 批次内所有账号最近 5 分钟内都发起过刷新，整批跳过；只要有一个超过 5 分钟，整批刷一次。
   - 批次触发后 5 分钟内不再自动触发；刷新失败同样计入，避免反复重试。
   - 手动刷新不受门槛限制。

4. **菜单栏来源的频率仍由设置决定**
   「低额度时提高菜单栏刷新频率」的开关、阈值与 15/30/60 秒加速周期保持不变，只作用于菜单栏来源。没有触发加速时，菜单栏来源按现有基础周期刷新：ChatGPT 30/60/120 秒自适应，DeepSeek / Google 约 5 分钟。

5. **DeepSeek 官方状态页同口径收窄**
   取消后台 5 分钟定时；改为概览页或 DeepSeek 页显示补刷时，距上次读取超过 5 分钟才读一次（公共页面，无凭证）。

6. **手动路径保持强制语义**
   页头「刷新全部」、品牌页「刷新」、点火后的确认刷新不受门槛约束。

## 口径（已与用户确认）

- 5 分钟门槛用整批判断，不做逐账号跳过。
- 批次不包含菜单栏正在显示的账号，它只由自己的周期循环、手动刷新与点火确认刷新维护。
- 启动只刷菜单栏来源，不预热全量；从未取数的账号视为需要刷新，首次打开页面时按批次规则补刷。
- 打开面板与面板内切换标签都按当前显示页面决定批次。
- 批次是否新鲜以最近一次刷新发起时间为准（含失败尝试）；任何覆盖该账号的刷新都会更新时间，从而自然推后下一次自动补刷。
- 独立详情窗口与 popover 使用同一套判定与同一份时间台账。

## 非目标

- 不改菜单栏显示格式、设置界面布局、账号管理与点火逻辑。
- 不改任何端点、凭证边界与既有失败重试策略（ChatGPT 重试阶梯、Provider 失败预算保持现状）。
- 不增加用户可见的请求统计或通知。

## 验收要点

- 菜单栏显示 O1 时只有 O1 按周期刷新，O2、G1、DS1 等没有后台请求。
- 打开概览页补刷未显示账号一次；5 分钟内再打开不触发，超过 5 分钟后打开触发。
- 打开 ChatGPT 品牌页只补刷 OpenAI 账号；Gemini / DeepSeek / Command Code 不受影响，5 分钟规则一致。
- 面板内切换标签按同一门槛补刷当前页面。
- 手动刷新始终立即生效。
- 完整回归 0 失败；真实界面与本机请求节奏复验通过。

本次修订只处理四件事：移除菜单栏品牌图标；新增两排重置时间分段条；修复菜单栏详情弹层点击外部不收起；将菜单栏异常提示统一为前方一个感叹号标记。

### 1.1 必须达到的结果

1. 正常且空间充足时，菜单栏文字从 `5H` 开始，继续显示原有 5 小时与周额度百分比，不再显示 `M²` 或其他品牌图标。

3. 两排细线分别表达距离 5 小时窗口、周窗口重置的剩余时间。亮区随时间从右侧向左侧缩退，到最左端时归零。
4. 点击菜单栏打开的详情弹层后，点击屏幕其他位置可以收起，且该次点击仍能作用于原目标。
5. 菜单栏同一时刻最多显示一个异常图形标记，统一放在文字前方，删除尾部重复标记。

### 1.3 两处需求解释

**周条的单位：**用户原文为“分 7 个短线，每个短线代表一周”。根据“周重置”及与五小时计时一致的上下文，本方案采用 **7 段，每段 1 天，合计 7 天**。每段一周将变成 7 周，无法表达当前周窗口。此项是明确标注的设计解释，交付时需告知用户；除非用户更正，按本方案执行。

**从右到左的方向：**采用“右侧先变空，亮区保留在左侧”。剩余 2 小时时左侧两段满亮、右侧三段暗；最后一段在最左侧耗尽。不能把亮区固定在右侧并从左侧开始清空。

## 3. 菜单栏视觉规格

### 3.1 最终布局

采用 **文字在上，两排细线在下** 的布局。理由：保留文字的主要阅读位置，两类时间在同一区域顺序呈现，周条自然位于五小时条下方。

```text
5H 78% | W 42%       ← 原有额度文字，11 pt
━━━━ ━━━━ ━━━━ ━━━━ ━━━━  ← 5 小时剩余时间，5 段
━━ ━━ ━━ ━━ ━━ ━━ ━━       ← 周剩余时间，7 段
```

示意图只表达上下关系与段数，实际两排的左端和右端必须严格对齐同一文本容器。示例数字仅用于需求解释和测试，不能写入生产界面作为缺省数据。

- 正常完整文字保持 `5H 78% | W 42%` 的现有格式与剩余额度口径。
- 不新增闹钟、电池外壳、百分比数字、5H/W 重复标签或品牌图案。
- 保留当前字号、系统字体及正常文字颜色；只调整垂直位置以给两排细线留出空间。
- 文字与细线作为同一个可点击菜单栏状态项；细线不单独响应点击或拖动。
- 避免默认隐式动画、闪烁、渐变、阴影和持续发光效果。

### 3.2 尺寸与绘制方法

以下尺寸为实施起点，最终以真实 macOS 菜单栏截图验证；允许小范围调整间距与细线高度，但不得改变段数、方向、字号及上下顺序。

| 项目 | 起始参数 |
| --- | --- |
| 字号 | 11 pt，与基线相同 |
| 单排细线高度 | 1.5 pt，按实际屏幕 scale 对齐像素 |
| 同排段间距 | 2 pt，两排使用同样间距 |
| 两排线之间 | 1 pt |
| 文字与第一排间距 | 1 pt |
| 左右内边距 | 优先沿用当前合计 12 pt，由现有布局测量决定 |
| 圆角 | 不超过细线高度的一半 |
| 亮区 | 系统适配的前景色，正常约 85% 不透明度 |
| 空段轨道 | 同色约 20% 不透明度，增强对比模式可适当提高 |

完整文字容器的实测宽度记为 L；不包含外侧 padding 和独立警告标记宽度。两排轨道都使用 L。

```text
segmentWidth = (L - (segmentCount - 1) × gap) / segmentCount
```

五段与七段的单段长度不同，但两排总宽度完全相同。不能把五小时条只放到 `5H xx%` 下方，也不能把周条只放到 `W xx%` 下方。

应采用文字决定理想宽度、进度层消费已确定宽度的布局，例如文字承载测量配合 overlay/background，或受约束的组合视图。避免无约束 GeometryReader、Spacer 或 `.frame(maxWidth: .infinity)` 改变 `fittingSize`，造成状态项被测成数百点宽。首次布局的 fallbackWidth 也必须合理，且随后被真实测宽替代。

整体高度应适配 `NSStatusBar.system.thickness` 和实际按钮内容区。优先压缩空白与细线高度，保持文本字号；不能写死 24 pt 后假设所有屏幕一致。要求文字、细线均不裁切、不与菜单栏边缘粘连、不覆盖其他状态项。

### 3.3 空间不足与旧 icon 模式

保留现有刘海检测、隐藏检测、扩缩防抖和位置保存机制，不因本次去图标取消这些能力。

1. full：`5H 78% | W 42%`，显示两排完整时间条。
2. compact：采用 `5H 78% W 42%`，去掉分隔竖线及多余空白，仍以 5H 开头，仍显示两排时间条。不得再插入 M²。
3. 最小兜底：原 `.icon` 枚举可以保留作为内部兼容名称，但正常视觉改为纯文字 `5H`；需要警告时为前方一个警告加 `5H`。此模式隐藏两排时间条，不将 7 段挤成不可辨认像素。点击后可在详情查看完整数据。

最小兜底只用于实际空间不足，不得作为默认模式。如果有已存在的用户固定模式设置，同步明确其新视觉含义，避免界面仍承诺“图标”却显示文字。实施前先验证该设置实际存在及接线，不凭 README 描述扩大实现范围。

最小模式是屏幕物理空间不足的明确例外；完整与紧凑模式必须实现两排条覆盖全部额度文字。恢复空间后，沿用现有谨慎扩展策略，不能为显示双条破坏防抖。

## 4. 时间进度模型与算法

### 4.1 输入和数据来源

对每个窗口独立使用真实 snapshot 中的 `kind`、`windowDurationMinutes`、`resetsAt` 和同一帧的系统当前时刻 `now`。

- fiveHour：5 段，总时长 18000 秒，每段 3600 秒。
- weekly：7 段，总时长 604800 秒，每段 86400 秒。
- 窗口时长必须与目标 kind 一致。未知窗口不映射到任一时间条。
- 不能以额度百分比、启动时间、最近刷新时间、首次请求时间或本地累计 tick 推算重置时间。
- 同一时刻，额度变化但 resetsAt 不变时，时间条保持不变。
- 以绝对时间差计算；时区仅影响时间文案。周窗口不按本地周一、周日或午夜对齐，也不按夏令时日历天累计。

### 4.2 纯函数与部分填充

建议在 Core 新建 `ResetTimeProgress.swift`，或使用职责等价的独立文件。函数显式接收 `now`，返回可测试状态与每段填充比例，不依赖 SwiftUI、系统网络或内部定时器。

```text
remaining = resetsAt - now
clampedRemaining = min(max(remaining, 0), totalSeconds)
units = clampedRemaining / secondsPerSegment

for i in 0..<segmentCount:    // i 从视觉最左侧开始
    fills[i] = min(max(units - i, 0), 1)
```

每段先绘制完整低透明度轨道，再从该段左端叠加 `fills[i] × segmentWidth` 的亮区。随着时间减少，当前最右侧亮段的右边界向左移动。段间空隙不计入时间占比。

| 剩余时间 | 由左到右的 5 段填充比例 |
| --- | --- |
| 5 小时 | `[1, 1, 1, 1, 1]` |
| 4 小时 30 分 | `[1, 1, 1, 1, 0.5]` |
| 2 小时 | `[1, 1, 0, 0, 0]` |
| 2 小时 30 分 | `[1, 1, 0.5, 0, 0]` |
| 30 分 | `[0.5, 0, 0, 0, 0]` |
| 0 秒或已过期 | `[0, 0, 0, 0, 0]` |

周条同理：剩余 3 天半为 `[1, 1, 1, 0.5, 0, 0, 0]`。不使用向上取整把剩余 1 分钟显示成整整一小时。

### 4.3 状态与异常处理

建议返回 `active`、`awaitingRefresh`、`unknown`、`invalid` 等明确状态，并将缓存属性与上述时间状态分开组合。可使用不同命名，但必须覆盖以下行为。

| 场景 | 必须行为 |
| --- | --- |
| 有合法未来 resetsAt | 按真实时间差显示 |
| resetsAt 恰好到达或过去 | 全空，提示“已到重置时间，等待刷新确认”；不得自行恢复满格或自动加 5 小时/7 天 |
| 服务返回新的合法 resetsAt | 使用新时间重新计算，允许直接跳回新的剩余比例 |
| 一个窗口缺失 | 该排 unknown；另一排独立正常显示 |
| resetsAt 缺失或不合法 | unknown，不显示虚构时间进度 |
| duration 与目标 kind 不匹配 | invalid，不擅自归一到 5 小时或一周 |
| remaining 超过总窗口时长 | 允许最多 60 秒的时钟/服务误差并夹到满格；超过 60 秒标为 invalid，不长期伪装满格 |
| 非有限数值、异常 Date 输入 | invalid，不崩溃、不传递 NaN 到绘图 |
| 使用可信缓存且 resetsAt 尚未到达 | 可按缓存时间继续计时，亮区降低透明度，保留唯一前方警告；提示明确写“依据缓存重置时间” |
| 缓存 resetsAt 已过期 | 全空且保留缓存警告，等待真实刷新，不推断新周期 |
| 无任何有效快照 | 额度按原有未知占位显示，两排 unknown；加载状态与确定失败状态应区分 |

unknown/invalid 排显示更淡的 5 段或 7 段轨道，并在该排中部覆盖小型 `?` 文本；问号用于区分未知与已到期的空条，不是额外感叹号。不得仅用“全空”同时表示未知和到期。悬停提示与无障碍文字须说明具体状态。显示缓存时建议亮区不透明度约 45%，轨道约 15%；增强对比模式允许提高，以可辨识为准。

60 秒容差为本轮防御性显示策略，不是服务协议事实。用例必须覆盖 60 秒边界及超出边界，实施报告记录实际采用值。

到达重置时间仅说明时钟已到达服务曾报告的时间，不证明服务已更新额度。菜单栏百分比不得自动归零或变成 100%。详情如仍出现“已于某时重置”这种确定性表达，需针对该状态最小改为“已到重置时间，等待刷新确认”，避免与菜单栏相互矛盾；不得借机改版整个详情页面。

### 4.4 时钟更新和生命周期

- 优先复用现有每秒本地 tick，在每次绘制计算时重新读取系统 Date，或发布同一份 `now` 给两排共用。
- 禁止使用 `remaining -= 1`，否则睡眠、主线程延迟或系统调时会累计误差。
- 新 snapshot 到达后，下一个界面更新周期内必须应用新 resetsAt，即使额度数字未变。
- 睡眠唤醒或系统时间改变后，应立即触发本地重算；不依赖应用持续运行满五小时。
- 唤醒通知需要使用正确的 `NSWorkspace.shared.notificationCenter`；当前几何监听将相关通知加在默认中心，实施时核实并修正与本轮唤醒行为相关的接线。
- 时钟向前跳过重置点时变为空；向后跳时重新计算并遵守超时范围规则。
- 单纯时间更新不得触发服务刷新、额度重置操作、每秒日志或每秒状态项宽度重建。
- 当前 `objectWillChange` 观察会因 tick 触发 `refreshLabel()` 并清空签名；实施应将时间绘制与影响尺寸的变化区分，避免每秒重复测量所有模式。不能通过完全停止时间更新来规避。
- 保留当前 Codex 与 Provider 刷新节奏和失败预算。到期后的新数据由现有刷新机制获取，本轮不强制额外请求。
- 定时器、通知 token 和订阅由明确 owner 管理；stop/uninstall/关闭时正确释放，重复启动不叠加。

## 5. 移除菜单栏图标与警告去重

### 5.1 统一输出

正常：`5H 78% | W 42%`。

缓存或确定读取失败：`⚠ 5H 78% | W 42%` 或 `⚠ 5H – | W –`。

前方 `⚠` 为单个异常标记的示意，可采用系统警告图形以避免彩色 emoji 尺寸不稳；二者选一个，不能叠加。正常状态不保留品牌图标占位空隙。尾部不得再出现 `!`、`⚠` 或等价警告图形。

警告与“移除前方图标”不冲突：品牌标识删除；异常时保留用户指定的前方告警。额度文字和两排时间条仍对齐同一文本容器，前方警告单独占位，不改变条的时间含义。

### 5.2 实施要求

1. 将警告的决定逻辑集中到单一状态表达；full、compact、最小模式使用同一语义。
2. `UsageFormatting` 不再在末尾追加警告；可保持函数签名兼容，但明确告警由哪一层绘制。同步检查全部调用方与无障碍标签，不允许部分调用方失去缓存提示。
3. 初始加载可以显示未知占位，不凭初始 `.unavailable(.other)` 就宣称已发生读取失败。结合 loading/connection 状态，区分“尚未取得数据”与“读取已经失败”。
4. 部分额度不可用时最多一个前方警告，并在详情指明缺失窗口。仅重置时间未知但额度可用时，使用该排 `?` 和提示，不新增感叹号。
5. 未发生读取失败、仅刚到重置点时不新增错误警告，用时间状态提示等待刷新即可。
6. 不删除详情中必要的错误解释，不影响其他 Provider 的独立状态图形；本轮“一个警告”约束针对菜单栏这一状态项。
7. 不用对拼接完成的字符串全局替换感叹号来掩盖问题，要消除重复来源。

## 6. 点击外部收起详情弹层

### 6.1 作用范围

必须修复的是点击菜单栏状态项打开的临时 `NSPopover`。普通“额度详情”窗口、GLM 独立登录窗口及其他独立设置窗口仍遵守普通窗口行为，不因外部点击自动关闭。菜单栏被遮挡时的普通详情窗口兜底保留。

实施前确认报告中的“详情页”实际属于哪一种窗口。如果普通菜单栏点击错误地进入了独立窗口路径，应修正该路径；不要把所有 NSWindow 设置为失焦关闭。

### 6.2 预期行为

| 用户操作 | 预期 |
| --- | --- |
| 左键点击菜单栏项 | 打开弹层；再次点击关闭，不能关后立即重开 |
| 现有右键入口 | 保持现有打开/关闭语义，除非实际代码另有明确上下文菜单 |
| 点击弹层外桌面、其他应用、其他屏幕 | 弹层收起；原点击正常传递 |
| 点击本应用的其他独立窗口 | 弹层收起；该独立窗口不关闭 |
| 点击弹层内部控件、滚动、输入 API Key | 弹层保持；控件正常响应 |
| 弹层内弹出下拉菜单、sheet 或警告框 | 按所属关系处理，不被外部点击逻辑误关 |
| 按 Esc | 无嵌套交互时关闭弹层；有 sheet/菜单时优先交由嵌套交互处理 |
| 切换到其他应用、失去活动状态 | 临时弹层收起，独立窗口保留 |
| 关闭再打开，连续 20 次 | 无额外监听器、重复回调或开关闪烁 |

### 6.3 排查与实现建议

1. 先用当前基线记录打开路径、popover.isShown、窗口类别和关闭现象。仅记录脱敏状态，不读取输入内容。
2. 保留 `.transient`，核查激活时机、窗口 key 状态、弹层 delegate 与按钮事件传播。不能仅凭属性存在便报告成功。
3. 若系统默认关闭不足以覆盖场景，在 `StatusItemController` 内集中维护关闭策略。可以组合应用失活通知和公开 NSEvent 的 local/global 鼠标监听；具体方案须验证当前 macOS API 行为，不能假设 global 能同时覆盖本应用内事件。
4. 监听仅在弹层打开期间安装；所有关闭路径，包括系统自动关闭，都需集中清理。使用 popover delegate 或等价生命周期回调做兜底，避免只在 `closePanel()` 清理。
5. 本地监听返回原事件，不吞掉别人的点击。外部点击判断正确区分弹层、所属子界面和状态项按钮，必要时在一致的屏幕坐标系判断。
6. 排除状态项按钮的本次 toggle 事件，防止监听先关闭，按钮随后又打开。也要防止打开的同一次点击触发新监听立即关闭。
7. 不引入全局键盘监听、事件 tap、辅助功能/输入监控权限请求，不请求屏幕录制权限作为功能前提。
8. 不因修复收起行为破坏之前用于 SecureField 的应用激活和焦点逻辑。
9. `uninstall()` 必须幂等释放监听，退出不遗留回调；弱引用避免 owner 环。

## 8. 验证与验收矩阵

### 8.1 自动测试

优先测试可观察行为与纯函数，避免只搜索源码字符串来证明功能。

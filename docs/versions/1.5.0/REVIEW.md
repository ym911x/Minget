# v1.5.0 审核

状态：代码、完整自动测试、Release 构建、严格签名及本机备份安装已完成；设置、详情切换和账号管理窗口已有真实界面证据。菜单栏重复点击修复等待签名包用户复验；首次连接和换机验收待完成；未发布。

审核重点：切换标签不能重复发起刷新；`account/login/completed` 必须匹配当前登录 ID 与 app-server 连接代次；取消后旧通知不能更新状态；凭证只经现有 Keychain 路径；缓存与实时额度文案区分；旧版升级不触发首次引导。

差异复核：详情筛选仅读取 `DetailPreferences`，没有写入菜单栏来源或调用刷新；偏好变更时重新创建浮窗内容明确传入 `refreshOnAppear: false`。登录与额度读取共用已有 `UsageService`，完成通知需同时匹配当前登录 ID、服务代次和连接代次；取消和停止清除进行中状态。早于启动响应的完成通知由待匹配表处理，匹配后只回调一次。Key 表单复用原有 Keychain 存取和只读验证路径；连接文案区分已保存、缓存和实时数据。

用户实测指出原签名包的菜单栏第二次点击仍不关闭，而 Esc 与窗口切换正常。改为 `.applicationDefined` 并由应用明确处理外部点击、Esc 和应用失焦后，用户连续试点几十次仍见偶发需要第三下；再改为按下事件处理及同一事件编号去重，用户反馈仍经常需要再点一次。重叠区域改判为状态按钮后，用户再次报告失败。现场本地事件记录显示：全局监听器将部分状态按钮点击判为外部点击并先关闭浮窗，随后同次点击的状态按钮动作又打开。状态按钮动作的 `NSApp.currentEvent.eventNumber` 为 `0`，因此编号去重无效。最终移除会抢先处理按钮点击的全局监听；按钮动作负责正常切换，本地监听只处理本应用内的外部点击与浮窗箭头重叠区，应用失焦处理其他应用点击。重叠区回归测试保留，当前签名版已安装，真实重复点击及外部点击复验仍待用户结果。账号管理的既有缓存状态不再误写为“正在读取额度”。

完整测试及签名结果见 `IMPLEMENTATION_REPORT.md`。未触发点火或重置额度消耗。

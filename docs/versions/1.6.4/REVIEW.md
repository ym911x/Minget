# 1.6.4 审核

审核对象：`codex/minget-1-6-4` 工作区相对 `main@73c3f9a` 的全部改动。本文件是实施者本人的代码复核记录，没有宣称由独立审查者或第二台设备验收。

## 复核结论

- **顺序规则**：`OverviewReorder.resolve` 以偏好顺序为准，仅保留当前可见 ID，未列出的可见 ID 按来源顺序追加末尾，重复 ID 只保留第一次。这保证首次升级时顺序与 1.6.2/1.6.3 的平台分组顺序一致，新增账号沉底而不会打乱已有行。
- **越界与退化输入**：`move` 对越界目标收敛到 `0...count`，未知 ID 原样返回；`dropIndex` 在 `pitch <= 0` 或 `count <= 1` 时返回收敛后的原位。对应测试覆盖越界、单行、非法间距。
- **持久化边界**：只写入账号 ID 字符串数组到 `overview.accountOrder.v1`，不写名称、金额、连接或凭证。读取路径（`resolvedOrder`）不落盘，未拖动过的用户不会产生偏好；`commit` 过滤不可见 ID，拖动途中被移除的账号不会残留。空数组时移除键，避免留下空壳。
- **拖动状态归属**：拖动状态位于 `UsagePanelView`，不在行内，行每 30 秒的 `TimelineView` 重绘不会重置拖动；拖动开始时冻结顺序，模型在拖动期间发布新快照不改变行序。松手统一走一次 `move` + `commit`。
- **手势隔离**：手柄是行内 Logo 上的高优先级手势，位移超过 3 pt 才接管该次按压，短按（无位移）仍由行按钮进入详情；行内其他区域没有任何新手势。手柄的命中区外扩 4 pt，但不会覆盖名称或图形区域。
- **跟手精度**：拖动位移在窗口全局坐标系测量。行内局部坐标系会以被拖动后的行自身为参照，形成位移反馈，实测表现为抖动与滞后；全局坐标系只反映指针自身的移动。
- **位移与动画**：被拖行只承担指针位移，其槽位由 `dragDropIndex` 表达，因此不会被自身位移重复推动（纯函数 `OverviewReorder.dragOffset`，有回归测试）。滑让位移是整数格 × 76 pt。被拖行的位移显式不参与动画，其余行的位移变化统一走 `reorderAnimation`。1.6.1 起用于抑制页面隐式动画的 `.transaction { $0.animation = nil }` 已移除：它覆盖整个子树，会连排序动画一起清空；页面内没有其他动画来源，服务切换与尺寸变化的表现不变。
- **未触碰的面**：`AccountRegistry`、菜单栏来源、`displayNames`、点火计划与刷新调度均未修改；概览高度函数未改，七账号完整显示与短屏兜底回归通过。
- **凭证与网络边界**：本轮只新增本地偏好读取与视图手势，没有新增网络调用、模型端点、Keychain 读取或认证文件访问；示例渲染使用合成账号与 `InMemoryCredentialStore`。
- **无障碍**：手柄带「拖动排序：<名称>」标签与可调操作，上移/下移走与拖动相同的提交路径，越界时不动。

# 1.4.0 点火模型统一与菜单栏自适应刷新需求

状态：已实现、通过发布验收并发布。本版本不自动执行真实模型请求；真实低额度服务轮询保留为发布后现场观察项。

1.4.0 是一次小版本更新，范围限定为两个点火路径的模型统一，以及菜单栏当前显示来源的低额度自适应刷新。上一版本的 LaunchAgent 时间、点火计划结构、额度语义、凭证边界和详情页布局不在本版本中改动。

## 1. 版本目标

1. 应用内 Command Code 手动点火、应用内 Command Code 定时点火共用 `deepseek/deepseek-v4.1-flash`。
2. 外部 `minget-fire` 的 Command Code 路径继续使用同一模型标识；本版本只核对其一致性，不改 LaunchAgent 的时间表或触发方式。
3. 当菜单栏当前选中的 ChatGPT 账号额度较低，或当前选中的 DeepSeek 菜单栏余额较低时，仅为该来源增加一条补充刷新回路。
4. 刷新周期和全部阈值均可在设置中调整，并持久化到应用自己的 `UserDefaults`。默认值应适合低额度预警而不制造持续高频请求。

## 2. 自适应刷新规则

### 2.1 默认值与可调范围

- 开关：默认开启。
- 补充刷新周期：默认 30 秒，可选 15、30、60 秒。
- ChatGPT 5 小时剩余阈值：默认 50%，范围 0% 至 100%。
- ChatGPT 周额度剩余阈值：默认 15%，范围 0% 至 100%。
- DeepSeek CNY 余额阈值：默认 15.00 元，输入必须为大于等于 0 的有效数字。

### 2.2 ChatGPT

- 仅检查菜单栏当前选中的 Profile。
- 5 小时剩余百分比严格小于阈值，或周额度剩余百分比严格小于阈值，即进入补充刷新。
- 恰好等于阈值不触发；缺失或非法窗口不触发。
- 该回路只调用当前 Profile 的既有只读刷新，不重置失败预算，不刷新另一个 Profile。

### 2.3 DeepSeek

- 仅检查菜单栏实际显示的余额来源。
- 只有实际显示币种为 CNY 时才应用“低于阈值元”的判断；用户将菜单栏切换到 USD 等其他币种时，不把其他币种金额当成 CNY。
- 余额严格小于阈值时进入补充刷新；余额、币种或报告不可用时不触发。
- 缓存余额可以触发补充刷新，以便尽快恢复实时数据；缓存仍必须按既有语义显示为缓存。

### 2.4 调度边界

- 低额度补充回路只服务菜单栏当前选中的来源；详情页的 ChatGPT 退避、DeepSeek/Command Code 提供方刷新、时钟 tick 和手动刷新保持原有节奏。
- 当前来源切换时，旧来源不再获得补充回路，新来源按自己的快照和阈值重新计算。
- 已有请求进行中时不得叠加同一来源请求；沿用现有 Profile/Provider 的合并与停止语义。
- 数据恢复到阈值以上后，补充 timer 取消，回到既有普通刷新。
- 设置输入无效时应暂停对应的加速行为，不用估算值替代。

## 3. 凭证与网络边界

- 本版本不新增 HTTP 端点，不把模型请求放进应用 HTTP 层。
- Command Code 点火仍只能通过用户明确授权的官方 CLI 路径执行，使用隔离 `HOME`、固定最小参数、Keychain Key 和输出丢弃规则。
- 刷新策略、设置和测试不得保存或显示 API Key、OAuth token、Cookie、CLI 输出、真实会话数据或原始响应。

## 4. 完成定义

1. 应用内 Command Code 固定参数和测试均指向 `deepseek/deepseek-v4.1-flash`，外部脚本核对为同一模型。
2. 设置中可以开关低额度加速、调整周期和三个阈值，并可恢复默认值。
3. 严格边界、ChatGPT OR 关系、DeepSeek CNY 选择、当前来源隔离、无效输入 fail-closed 和 timer 停止均有确定性测试。
4. 全量自动测试、Release 构建、严格签名和退出清理通过。
5. 真实签名包中确认设置项可见、输入可保存、切换菜单栏来源后只有当前来源加速；不把自动测试或构建结果写成真实服务验收。

## 5. 明确非目标

- 不修改 LaunchAgent 时间表、`minget-fire` 的账号编排、Command Code 定时触发权限或点火提示词。
- 不增加第三个 ChatGPT Profile、通知、Fire All、长期点火历史、LaunchAgent 管理或新的提供方端点。
- 不执行真实模型请求或消耗额度作为自动化验收步骤。
